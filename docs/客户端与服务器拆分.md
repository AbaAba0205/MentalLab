# 客户端与服务器拆分（0.4）

本说明替代历史技术设计中“浏览器保存记录、聊天刷新丢失、账号尚未接入”的实现描述。

客户端 `client/` 与服务器 `server/` 各有 package.json、锁文件、构建配置、环境模板、说明和测试，可以分别安装及发布。根目录 npm workspaces 只用于本仓库开发便利。两边各自保留运行所需的领域类型和校验代码，不跨目录导入运行代码；协议变化需同步两边并通过集成测试。

浏览器 → 客户端同源 `/api/*` → Next.js rewrite → 服务器。服务器同时提供独立管理网站。身份使用 HttpOnly Cookie，密码使用 scrypt，服务器只存会话摘要。注册始终是普通用户；管理员由服务器命令创建，所有管理 API 都检查数据库中的当前角色和停用状态。

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/health` | GET | 数据库和 AI 配置状态，不返回密钥 |
| `/api/auth/register`、`/api/auth/login` | POST | 认证并设置会话 Cookie |
| `/api/auth/me` | GET | 读取当前账户 |
| `/api/auth/logout` | POST | 撤销当前会话 |
| `/api/account` | PATCH | 确认使用说明 |
| `/api/records` | GET、POST、DELETE | 读取、新增、清空自己的记录 |
| `/api/records/:id` | DELETE | 删除自己的单条记录 |
| `/api/records/import` | POST | 显式导入旧版个人记录，单次最多 500 条 |
| `/api/chat/conversations` | GET、POST | 读取会话列表与上次选择，创建独立会话 |
| `/api/chat/conversations/:id` | GET、PUT、DELETE | 读取、保存或删除自己的指定会话 |
| `/api/chat/conversations/:id/select` | POST | 切换并保存上次选择的会话 |
| `/api/chat/history` | GET、PUT、DELETE | 兼容旧客户端，读写/清空上次选择的会话 |
| `/api/chat/turn`、`/api/scenario/turn` | POST | 已认证用户的 AI/预设练习 |
| `/api/config/reminders` | GET | 从服务器读取公开提醒展示内容 |
| `/api/admin/overview` | GET | 管理员读取用户、记录、对话与操作日志 |
| `/api/admin/users/:id` | PATCH、DELETE | 停用/启用或删除普通用户 |
| `/api/admin/record` | DELETE | 通过 userId 和 id 删除指定记录 |
| `/api/admin/history` | DELETE | 通过 userId 和 channel 清空对话 |
| `/api/admin/reminders` | PUT | 更新提醒内容及轮换间隔 |

除健康状态、提醒内容、认证入口和管理登录页面外，所有数据接口都要求认证。业务写入会校验 Origin、JSON 内容类型、请求体大小和结构。记录查询和修改始终以会话身份为准，不使用客户端提交的 userId；普通用户不能授予自己管理员权限。管理员变更有日志，删除用户会通过外键级联删除会话、记录及对话。

新用户不生成示例记录。旧版浏览器练习数据需要用户主动导入，成功后再移除浏览器副本，重复按用户及记录 ID 去重。服务器中的旧版随心聊历史在建库升级时通过事务自动迁移到独立会话，迁移只执行一次，消息及原日期保留。

随心聊以 `conversations` 存储独立会话，`chat_selection` 保存账户上次选择；新账户或删除最后一个会话后创建空会话。标题取第一条用户消息前 40 字，清空消息后保留原标题。列表按最近更新排序。删除会话不删除保存过的练习记录；删除账户级联删除会话及选择状态。管理员可按会话 ID 单独查看、清空对话。

数据库写入成功才作为客户端保存成功；失败保留表单。聊天按会话 ID 顺序提交完整快照，回复/保存未完成或保存失败时禁止切换，避免串写和丢失未保存内容。切换保留当前页面的输入草稿，刷新后草稿丢弃。每次模型调用只提交当前会话的近期上下文。多个设备同时编辑同一会话采用最后写入覆盖，当前不提供实时合并。

情境接口保存最近一次提交成功的情境对话供管理查看，练习总结需要点击保存才成为个人练习记录。课程及训练静态内容属于应用版本，仍随客户端发布；动态提醒配置归服务器管理。
