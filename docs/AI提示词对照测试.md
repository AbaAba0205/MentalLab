## 结论

已完成全部 36 次真实模型调用，时间为北京时间 2026-10-17 22:52:05–22:55:08，总历时约 183 秒。批次 ID：`prompt-evaluation-2026-10-17T14-52-05-846Z-5adb9c68`。

仅强化提示词，仍不能让模型稳定遵守输出格式。最接近用户问题的“关系矛盾”样例中，当前提示词和强化提示词各三次调用均返回普通中文，JSON 历史组的两次已完成调用也均为普通中文，另一次超时。JSON 接口参数组的三次返回均是合法 JSON，但其中一次为 `{}`，缺少应用必需字段。

这批样本支持优先增加接口输出约束、保留字段校验，并针对不合格结果纠正重试；不能把问题只归因于提示词文案，也不能把 `json_object` 当作完整业务结构的保证。接口 JSON Schema 支持情况、强化提示词与 JSON 模式组合的效果尚未实测。

## 测试设置

使用当前服务器已配置的 `https://llmapi.paratera.com`，模型 `DeepSeek-V4.1-Flash`；凭证只通过请求鉴权头传输，不写入报告或存档。所有测试对话均为脚本内的虚构样例，不读取账户数据库或重放用户聊天。

| 组别 | 唯一改变的因素 |
| --- | --- |
| `current` | 无；使用当前完整提示词和普通文字历史回复 |
| `strong_prompt` | 强化提示词：首尾强调 JSON 协议，说明历史文字不是格式示例，增加 JSON 示例；保留现有全部规则 |
| `json_history` | 仅将历史 assistant 文字包装为预期 JSON；系统提示词保持当前版本 |
| `json_mode` | 仅添加 `response_format={"type":"json_object"}`，检验该参数对实际输出的影响 |

三个固定样例为首次打招呼、朋友关系问题的多轮聊天、聊过矛盾后再次打招呼。每个样例每组重复三次，共 36 次调用，每组 9 次。组别顺序轮换；并发为 1，不自动重试，未因结果不佳重跑或挑选样本。所有组保持 `temperature=0.6`、`max_tokens=700`、单次超时 15 秒。

分别统计：实际调用数、收到 HTTP 200 且具有模型内容的次数、严格 JSON 语法通过数、生产解析与校验通过数、JSON 解析失败数、超时数和调用耗时中位数。非 2xx、网络超时、JSON 解析失败和其他校验失败分别报告；接口接受 JSON 参数不等于保证其执行。

实验脚本只用于评测，不修改应用当前提示词、生成参数、解析或安全策略。

## 解释范围与后续建议

1. 单组只有 9 次调用、3 个固定普通聊天场景，属于初步对照；顺序轮换而非完全随机，也没有验证长期可靠率。不能把 44.4%→66.7% 宣称为已证明的稳定提升，不能将 9/9 合法 JSON 解读为未来必然成功。
2. JSON 模式本次 9 次均被接口接受且都输出了合法 JSON，是格式遵循最好的单因素组。但一次 `{}` 说明它未保证必需字段。若供应商支持，应进一步测试带 `required`、字段类型和枚举约束的 JSON Schema；当前实验未验证该能力。
3. 可以保留清晰的格式指令和示例，但不应只靠重复强调。应结合接口输出约束、严格字段校验，以及针对具体解析/字段错误的纠正重试；不能直接把任意普通文字包装成合格结果而跳过安全与推荐校验。该组合需要下一轮验证，本次未替换线上配置。
4. 超时属于另一类问题，应结合供应商耗时和客户端/服务器总体时间预算单独排查。不能用修改提示词来解释或承诺解决这两次超时。
5. 本次仅验证输出协议及现有程序检查，不是心理支持内容质量、安全性、风险识别或训练适配的完整评测。三个场景不覆盖危机、恶意输入或复杂训练请求。
