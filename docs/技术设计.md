# 心晴技术设计

> 0.4 更新：项目现已拆为 `client/` 与 `server/`，加入注册登录、服务器数据库和管理后台。本文保留 0.3 设计背景；存储、账户、部署与接口现状以 [客户端与服务器拆分](客户端与服务器拆分.md) 为准。

版本：0.3　日期：2026-10-15　状态：比赛 MVP 核心闭环已实现

本文确定黑客松 AI 创业比赛版本的实现方案，并区分当前已实现的能力与后续开发范围。产品基线参考项目根目录的《项目文档.md》与《项目计划.docx》。比赛版优先覆盖考试压力场景，形成“签到 → 技能练习 → 反馈 → 复盘”的完整体验。

## 1. 交付形态与范围

电脑和手机使用同一套响应式网页。电脑适合课程阅读、完整练习及复盘；手机优先支持扫码进入、快速签到和短时练习。第一阶段不开发桌面客户端、独立 App 或微信小程序。

新增随心聊默认首页、对话内嵌训练及课程预留页，详见 [训练与陪伴聊天扩展](训练与陪伴聊天扩展.md)。课程尚未发布。

比赛版本已完成接地练习、CBT 想法整理、考试前行动计划及一个 AI 情境练习。课程库、家长端、学校后台、复杂成长地图和实时语音留到后续，避免分散开发时间。

当前工程沿用已有交互，并增加首次使用说明、三轮“向同学表达边界”情境、安全中断和现实支持入口。未配置模型或调用失败时，界面明确标注“预设练习”，不声称提供 AI 反馈。

## 2. 技术决策

| 层次 | 选型 | 决策理由 |
| --- | --- | --- |
| 全栈框架 | Next.js 16 App Router | 网页与服务端 API 同仓部署，减少黑客松联调成本 |
| 界面 | React 19 + TypeScript 严格模式 | 以组件和受控状态实现分步练习，约束数据结构 |
| 样式 | Tailwind CSS 4 + 现有 CSS | 保留已有响应式设计，新组件可逐步使用工具类；暂不开启 Preflight，避免重置现有样式 |
| 运行环境 | Node.js 22 LTS 或更新的受支持版本，推荐 24 LTS | 使用受支持的长期维护版本；依赖精确锁定并提交 package-lock.json |
| 服务端接口 | Next.js Route Handlers，Node.js runtime | 统一处理模型调用、鉴权和数据校验，第一阶段不拆微服务 |
| AI | OpenAI 兼容服务端模型适配层 | 默认模型名为 `DeepSeek-V4.1-Flash`，可通过环境变量更换，界面显示实际配置的模型 |
| 正式数据 | PostgreSQL + Prisma，后续接入 | 保存用户、授权、练习进度与结构化记录，支持账号下跨设备访问 |
| 验证 | ESLint、TypeScript、node:test + tsx、Playwright | 纯逻辑回归及桌面、手机完整交互验证 |
| 部署 | 支持 Node.js 的 Next.js 托管环境 | 单应用部署，按访问地区与现场网络选择服务商，公开环境必须 HTTPS |

不提前引入多 Agent、向量数据库或独立任务队列。少量审核技能先作为版本化内容维护；确有检索规模、长任务或吞吐需求时再加入对应组件。

## 3. 系统边界

```text
电脑浏览器 / 手机浏览器
        │ HTTPS，同一账号体系（后续）
        ▼
Next.js 页面与 React 交互组件
        │ 同源 API（后续业务接口）
        ▼
鉴权与输入校验 → 练习状态与安全规则 → 模型适配器
        │                  │               │
        ▼                  ▼               ▼
PostgreSQL          经审核的技能内容      模型服务 API
```

当前已实现页面、浏览器本地存储、预设练习、`/api/health`、`/api/scenario/turn`、服务端安全分流、模型调用和故障回退。账号与 PostgreSQL 仍属于后续目标架构。

页面布局、元信息与服务端接口位于 `src/app`；交互组件位于 `src/components`；记录类型、练习内容和纯函数位于 `src/lib`。涉及密钥、数据库或安全决策的后续模块放在服务端专用目录，并禁止客户端导入。

当前由 React 状态管理视图、弹窗、练习步骤和表单，计时器在退出步骤时清理。浏览器存储仅在客户端挂载后读取，避免服务端渲染访问 `localStorage`，或页面水合时覆盖历史记录。交互页面先输出稳定的加载状态。

## 4. 练习与 AI 的职责

AI 用于随心聊、推荐注册训练、模拟具体角色以及总结情境练习。固定训练由客户端通用执行器推进；服务端验证聊天输入、训练推荐资格和情境轮次，并优先处理安全分支。模型不能自行执行保存、通知或转介。完整的服务端持久会话状态机仍属于后续计划。

目标流程：

```text
确认用途及必要授权
  → 签到 / 选择练习
  → 输入检查与安全路由
  → 按经审核的步骤完成练习
  → 用户反馈与复盘
  → 用户选择是否保存

任意输入出现需要现实支持的信号 → 暂停普通训练 → 现实支持页面
```

后续每轮提交 `sessionId`、当前步骤版本、用户输入及必要的情绪强度。服务器读取会话并校验步骤，不信任客户端提交的状态或风险等级。返回有限结构，如 `message`、`nextAction`、`exerciseId` 和 `stepId`；输出经 schema 和允许动作列表校验后才驱动 UI。

安全规则结合上下文评估、模型输出校验、服务端硬性约束与固定资源页面。单个关键词函数或一段 Prompt 不足以构成完整安全机制。当前 `needsSupport` 只用于演示帮助分支，不宣称具备 L0–L3 风险评估能力。

比赛首个 AI 场景已经实现为“向同学表达边界”的三轮练习。模型只扮演已审核的场景角色；结束后依据明确的技能维度反馈。危机信号随时优先中断角色扮演。

## 5. 后续服务端接口与可靠性

| 接口 | 用途 | 当前状态 |
| --- | --- | --- |
| `POST /api/chat/turn` | 陪伴聊天、受限训练推荐、风险中断与回退 | 已实现 |
| `GET /api/health` | 返回服务与实际集成状态，无个人信息，禁止缓存 | 已实现 |
| `POST /api/scenario/turn` | 校验有限轮次情境、安全分流、模型生成及预设回退 | 已实现 |
| `POST /api/practice/sessions` | 创建用户授权范围内的练习会话 | 计划 |
| `POST /api/practice/sessions/:id/turns` | 验证步骤、执行安全路由并生成本轮引导 | 计划 |
| `POST /api/practice/sessions/:id/complete` | 保存结构化复盘，支持幂等提交 | 计划 |
| `GET /api/records` | 查询当前用户的记录 | 计划 |
| `DELETE /api/records/:id` | 删除当前用户的记录 | 计划 |

模型密钥只通过服务器环境变量配置，不使用 `NEXT_PUBLIC_` 前缀。`.env.example` 提供空白模板，本地使用被 Git 忽略的 `.env.local`。需要填写 `AI_API_KEY` 与 `AI_BASE_URL`；`AI_MODEL` 默认设为 `DeepSeek-V4.1-Flash`，可替换为同一服务商支持的其他模型。

AI 请求已限制单条与总输入长度、三轮上限、输出长度和单来源分钟请求数，并设置 15 秒上游超时。首版完整接收并校验结构化输出，暂不直接流式展示未经检查的生成文本。当前内存限流适合单实例比赛演示；多实例公开部署需要换成共享限流存储。

模型超时、不可用或输出不合格时使用已审核的预设内容，并显示“预设”标签。陪伴聊天对空内容或格式不合格的首次回复重试一次，两次均失败才回退。聊天回复在服务端完成结构与用语校验后，由客户端逐字呈现；这不是未经校验的模型流式输出。安全分支在模型调用前执行，不因模型失败而跳过。情境记录仍由用户主动决定是否保存到当前浏览器。

## 6. 数据与权限

第一阶段保留本地记录结构：`id`、`date`、`kind`、`title`、`mood`、`before`、`after`、`note`、`helpful`、`demo`。沿用存储键 `mind-island-demo-v1`，校验并补全旧记录的可选字段；损坏记录丢弃，不导致页面崩溃。清空状态持久化为 `[]`，避免刷新后重新出现示例记录。

浏览器存储按来源隔离，迁移到新的域名或端口不会自动带入旧站数据；需要时另外实现用户主动导入。当前没有跨设备或多标签页实时同步，不承诺本地数据安全加密。

数据库阶段建议使用以下实体：

| 实体 | 内容 |
| --- | --- |
| User | 最小化身份信息与地区配置 |
| Consent | 用途、版本、同意时间及撤销状态 |
| PracticeSession | 所属用户、技能版本、当前步骤、完成状态 |
| CheckIn / Reflection | 情绪签到、结构化练习结果与用户反馈 |
| Skill | 经审核的内容版本、适用条件与停止规则 |
| SupportResource | 地区、联系方式、核验时间与维护责任 |
| AuditEvent | 脱敏操作结果、策略版本和排障标识 |

在向真实用户开放云端记录前接入成熟鉴权方案，使用 HttpOnly、Secure 会话 Cookie，处理请求来源与 CSRF 防护。每次读写都在服务器检查记录归属，不能只在页面隐藏其他用户的数据。家长、学校与青少年数据权限分别建模，不默认允许机构或监护人读取完整记录。

默认不将聊天用于训练，不启用长期记忆；日志不记录用户原文、令牌或密钥。引入数据库时同时确定数据保留周期、删除与备份过期策略。共用电脑退出账号后清除会话和敏感页面状态。

## 7. 部署与比赛演示

开发使用 `npm run dev`；验收和部署使用 `npm run build` 后的 `npm start`，不以开发服务器作为公开服务。前端与 API 同源，未来数据库尽量与应用部署在同一地区。

模型供应商、应用托管和数据库地区在 AI 接入阶段确定，先实测比赛现场网络及手机访问，不默认依赖某个境外服务。当前静态插画与系统字体无需访问外部 CDN。

演示前准备独立测试账号、虚构案例与可清空的记录；校验电脑和手机各完成一次核心流程。AI 故障时能继续进入预设练习，现场说明实际运行模式。PWA、推送和离线缓存后置，不缓存敏感 API 响应。

## 8. 测试与验收

每次变更必须更新相关测试，通过验证后创建对应 commit。

- 单元测试：推荐边界、无效输入、旧记录兼容、损坏存储、非改善反馈、内容完整性及健康接口。
- 浏览器测试：签到、三种练习、前后步骤保存、计时器暂停与退出、刷新恢复、删除确认、清空、文本注入防护和存储权限失败。
- 兼容性：自动验证桌面与手机视口及无横向溢出；真实 iOS Safari、Android Chrome 与微信内置浏览器在公开试用前补做真机验证，手机视口模拟不等于真机兼容认证。
- 工程验证：ESLint、TypeScript、生产构建；GitHub Actions 在推送后重复执行检查和端到端测试。
- AI 与安全测试：覆盖 55 条安全与普通表达、输入边界、跨站请求、频率限制、模型正常与异常响应、未配置回退、多轮后出现风险及错误继续训练。真实用户试用前还需由专业人员审核并扩充语义变体。

不将关键词测试通过视为危机识别验证通过，不将用户情绪分数下降视为临床疗效。
