# 训练与陪伴聊天扩展

日期：2026-10-15

0.4 更新：界面和执行器路径现位于 `client/src/`，AI 及业务接口位于 `server/src/`；两端独立运行。领域协议在两端各自保留一份，新增模块需同步注册表并更新集成测试。账户和存储详情见 [客户端与服务器拆分](客户端与服务器拆分.md)。

默认首页为随心聊，原今日空间保留为独立导航。聊天、练习室和课程目录各自拥有独立组件；记录保存由外层工作区负责。

## 新增一个训练

1. 在 src/lib/training/modules/ 新增文件，导出满足 TrainingModule 的对象。用唯一的字面量 id（as const），填写名称、分类、时长、描述、适用条件 useWhen、步骤 steps。
2. 涉及认知分析或计划的训练配置 maxIntensity；现有想法整理和行动计划设为 3。没有此上限的模块只应是已审核的温和稳定练习。
3. 在 registry.ts 的 trainingModules 中注册一次。类型、分类筛选、练习室和 AI 可用目录自动包含新模块。
4. 步骤支持说明、文本输入、选项和计时器；required 标注必须完成的输入。执行器按 steps.length 推进，不再假定固定三步。新交互类型应先扩展 ExerciseStep 协议及 TrainingSession，再补充对应浏览器测试。
5. 新增覆盖适用条件、停止规则和实际交互的测试，执行 npm run check 和 npm run test:e2e 后提交。

TrainingSession 支持弹窗和 inline 两种容器。onSave 返回 Promise<boolean>，等待服务器确认持久化后才展示保存成功；失败保留表单。onHandoff 交给宿主处理现实支持，onClose 退出。训练内填写的答案不自动发送给模型。原有 exercises.ts 与 model.ts 保留兼容导出，记录格式兼容旧版导入。

## 课程位置

src/lib/courses.ts 定义筹备中的课程目录；src/components/courses.tsx 独立呈现课程空间。当前只有筹备方向和练习入口，没有已发布课时、学习进度或虚构完成情况。正式接入时可在此边界新增课程内容、课时、进度与课后训练 ID 的关联。

## 聊天协议与数据

POST /api/chat/turn 接收交替排列的 user / assistant 消息，最后一条必须为 user。最多 21 条消息（最近 10 轮及当前输入），用户单条最多 1000 字，总字符数不超过 14000，请求体限制为 64000 字节。客户端只发送文本，不发送本地练习答案或完整记录。

回复协议为 action（reply / handoff）、source（ai / fallback / safety）、reply 和 exerciseId。模型只提出训练 ID，服务器按注册表、用户拒绝和自评强度校验；界面展示卡片，用户点击后才启动。模型没有存储、通知或转介权限。

随心聊最近 200 条消息保存在服务器，切换导航保留，刷新或在其他设备登录可恢复。练习结果经用户主动保存后进入服务器账户记录。使用说明确认状态也由服务器保存。清空聊天会清空账户中的对话，不删除已有练习记录，也不代表危机已经解决。

## 用语与安全

- 模型先回应具体感受，通常 2–5 句、最多一个问题；不羞辱、责怪、诊断、指导用药、承诺疗效或建立排他依赖。用户只想聊时不推训练。
- 所有用户消息先做规则检查，已知风险直接返回固定现实支持；模型也可标记上下文风险。风险分支移除训练卡片并暂停普通聊天。
- 服务端验证 JSON、长度、已知不当表达、外部链接与训练资格；不合格、超时、未配置或服务异常回退为明确标注的预设回应。
- 思维整理和计划需要明确低强度自评；未知强度或中高强度只允许温和稳定训练。用户手动进入训练时再次自评。
- 输入语义与输出规则仍可能漏判或误判，不构成临床安全保证。对话上下文窗口有限；没有跨会话风险记忆、临床评估或真人接管。公开试用前仍需专业内容审核与安全评测。

## 验证

单元测试覆盖请求顺序与大小、注册表、拒绝和再同意、情绪强度、风险跨轮检查、模型风险标记、不当用语、伪造训练、模型故障、跨站与限流。浏览器测试覆盖默认入口、课程预留、嵌入训练及保存、跳过、风险中断、重试、清空、文本注入、导航保留与刷新清除。

Playwright 服务强制使用空模型配置，测试不向真实供应商发送内容。模型成功与风险响应使用可控替身验证；这不等同于真实供应商效果评估。
