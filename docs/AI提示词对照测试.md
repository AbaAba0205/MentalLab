# AI 提示词对照测试

日期：2026-10-17（北京时间）。

## 当前状态

评测脚本和本地验证已完成。真实模型对照实验尚未运行：自动审批拒绝向配置供应商发送 36 次完整提示词，需要用户明确确认目标与调用数量。不能将下文的实验计划或本地模拟测试当作真实模型的实验结果。

已保存的故障证据显示，同一次聊天请求第一次 15 秒超时，第二次 HTTP 200，但模型最终内容为普通中文，生产解析器报 `invalid_json`。第二次 `finish_reason=stop`，`completion_tokens=260`，`max_tokens=700`，没有截断迹象。它说明模型曾未遵守 JSON 指令，但不足以判断加强提示词是否有效。

## 实验计划

使用当前服务器已配置的 `https://llmapi.paratera.com`，模型 `DeepSeek-V4.1-Flash`；凭证只通过请求鉴权头传输，不写入报告或存档。所有测试对话均为脚本内的虚构样例，不读取账户数据库或重放用户聊天。

| 组别 | 唯一改变的因素 |
| --- | --- |
| `current` | 无；使用当前完整提示词和普通文字历史回复 |
| `strong_prompt` | 强化提示词：首尾强调 JSON 协议，说明历史文字不是格式示例，增加 JSON 示例；保留现有全部规则 |
| `json_history` | 仅将历史 assistant 文字包装为预期 JSON；系统提示词保持当前版本 |
| `json_mode` | 仅添加 `response_format={"type":"json_object"}`；需通过实际调用检验供应商是否接受和执行 |

三个固定样例为首次打招呼、朋友关系问题的多轮聊天、聊过矛盾后再次打招呼。每个样例每组重复三次，共 36 次调用，每组 9 次。组别顺序轮换；并发为 1，不自动重试，不因结果不佳重跑或挑选样本。所有组保持 `temperature=0.6`、`max_tokens=700`、单次超时 15 秒。单组的 9 次样本只能提供初步证据，不能证明长期可靠率。

分别统计：实际调用数、收到 HTTP 200 且具有模型内容的次数、严格 JSON 语法通过数、生产解析与校验通过数、JSON 解析失败数、超时数和调用耗时中位数。非 2xx、网络超时、JSON 解析失败和其他校验失败分别报告；接口接受 JSON 参数不等于保证其执行。

实验脚本只用于评测，不修改应用当前提示词、生成参数、解析或安全策略。

## 复现与存档

从 `server/` 运行 `npm run ai:evaluate`。该命令会使用服务器 `.env.local` 中现有的真实供应商配置，产生模型调用费用。

- 脚本：[evaluate-ai-prompts.ts](../server/scripts/evaluate-ai-prompts.ts)。
- 本地验证：[prompt-evaluation.test.ts](../server/test/prompt-evaluation.test.ts)，使用模拟供应商，不产生真实调用。
- 每次完整请求和原始响应保存在 `server/data/ai-interactions/`，与日常调用一样；请求 ID 包含评测批次和序号，便于关联。
- 批次计划和逐次结果保存在 `server/data/ai-prompt-evaluations/<批次ID>/plan.json` 与 `results.json`；每完成一次即保存当前结果，避免中断后丢失已完成样本。原始正文及批次数据均位于 Git 忽略目录。

## 待真实实验回答的问题

1. 强化提示词在相同聊天上下文下是否提高生产校验通过率？
2. 普通文字历史是否降低格式遵循率？首次打招呼没有 assistant 历史，应单独与多轮样例比较。
3. 供应商是否支持并执行 JSON 模式？若不支持，应依据 HTTP 错误原文报告，不能计作提示词失败。
4. 超时与格式失败分别占多少？不能把二者合并归因于提示词。
